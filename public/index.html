Processing progress

Key: NV = not verified · ? = count unknown · — = no value. Hover over headings for details.

Column guide
Meta / Files / Page
Catalogue evidence cutoff / latest file observation / page generation. File age uses the oldest observation. Fresh file checks do not refresh catalogue or execution records.
Run
Sequencing-run ID. A run may include samples unrelated to ANEMONE.
Set / Sets
Submission or sample-set IDs associated with the run, such as a DK code. These are not individual sampling events.
Groups
Three-letter groups from checked metadata. A code does not necessarily identify one sampling site.
Delivery
The selected delivery batch within a sample set; it may cover only part of that set.
Marker
The assay or marker being processed, for example MiFish.
Idx. S / Idx. C
Normal sample and control libraries listed in the complete MiFish index for the sample set.
Samp. / Ctrl.
Sample / control libraries in deliveries matched to metadata, counted separately per marker.
Done / C.done
Sample / control libraries with a processing result confirmed by a checked execution record. This confirms result coverage, not species-identification accuracy.
Miss. / C.miss
Expected sample / control libraries without a verified result after finalized processing. "?" means the count is unknown, not zero. These are not counts of missing species or raw FASTQ files.
State
Run or set view: the whole run or set. Sample breakdown: its sample libraries only. Delivery view: its job, samples and controls. A checked subset does not establish whole-run completion.
NV / RUN / OK / PART / FAIL
Not verified / running / all expected results verified / some results missing / job failed. These states require execution evidence; file presence alone does not certify success.
DB
ANEMONE DB registration, verified separately.
Release
Scientific dataset release, verified separately from this progress page.
Site group
For new matched rows, the group code comes from the verified sampling record. The sample-set Groups column follows the catalogue.
In breakdown
Number of matched sample libraries represented in the site breakdown. A smaller value than Samp. indicates partial coverage.
Results checked
When shown, the date and time the final roster was verified. This has a separate timestamp from the catalogue and the stage files.
Notes
Source-consistency issues or documented ID corrections requiring attention.
No code
Sample-library names without a recognized group-code pattern. These libraries remain included through checked metadata.
S.dmx / S.filt / C.dmx / C.filt
S denotes sample libraries and C denotes control libraries. Sample / control libraries with demultiplexed (both forward and reverse) or filtered files present at nonzero byte size; read content is not inspected. File presence does not certify successful processing. Runs use a checked MiFish file inventory for the sample sets listed in that row. Sample sets show the complete indexed MiFish set when verified. Delivery rows use the scoped submission, and breakdown rows cover the locations matched to sampling records. Incomplete inventory coverage appears as "?". A run inventory matches the indexed sample sets to the sets listed in Runs. Delivery views can contain a verified subset of a sample set. A missing sampling-location match does not suppress the corresponding delivery counts. 0 means no matching files found under the reviewed naming convention; it does not explain whether processing has started or files use another layout. These columns appear when a file inventory is connected.
Shared tables (JSON)
Header-only presence of tables shared by the analysis directory. This does not verify that a selected delivery is included or successfully processed.
